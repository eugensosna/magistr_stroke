# Рисунки, таблиці, формули, лістинги

Номери і підписи («Рисунок 1.1 – …», «Таблиця 1.1 – …», «(1.1)», «Лістинг 1.1 – …») генеруються автоматично.
Самі номери в тексті не пишіть.

## Рисунки

**Вихідний файл схеми** (SVG, у git) зберігається в `images/src/<name>.svg`, **растр для документа** — у `images/<name>.png`.
Після кожної зміни SVG перегенеруйте PNG:

```sh
magick -density 200 images/src/<name>.svg -background white -flatten images/<name>.png
```

Вимоги до схем:
- чорно-біле зображення на білому тлі (робота друкується): лінії чорні, заливка біла або світло-сіра;
- шрифт `Liberation Serif, Times New Roman, serif`, розмір 16–19 px при ширині полотна 800–1000 px;
- усі написи українською, без дрібного тексту;
- стрілки задаються через `<marker>`, пунктир (`stroke-dasharray`) означає асинхронні або необов'язкові зв'язки;
- SVG пишіть вручну або генеруйте Python-скриптом, як зроблено для `images/src/system-overview.svg`.

UML-діаграми (класів, послідовності, розгортання) можна будувати в PlantUML, зберігаючи `images/src/<name>.puml` поруч із PNG.
Графіки з даних (наприклад, FPS, точність, динаміка показників) будуйте в matplotlib: чорно-білий стиль, різні маркери й типи ліній, підписи осей з одиницями.
Скрипт кладіть у `images/src/<name>.py`, а дані — у `images/src/<name>.csv`.

Вставлення в текст (посилання стоїть **до** рисунка):

```asciidoc
Узагальнену схему застосунку наведено на рис. <<fig-system-overview>>.

[[fig-system-overview]]
.Узагальнена схема ігрового застосунку для дистанційної реабілітації
image::system-overview.png[Опис для alt,width=100%]
```

`width` задається у відсотках від ширини тексту. Для схем беріть 80–100 %, для скриншотів 60–90 %.
Назва рисунка пишеться без крапки в кінці. Скриншоти інтерфейсу зберігайте у PNG і не стискайте в JPEG.

Якщо рисунок запозичено, вкажіть джерело в назві: `.Архітектура MediaPipe Hands <<zhang2020>>`.

## Таблиці

```asciidoc
Порівняння наведено в табл. <<tbl-tracking>>.

[[tbl-tracking]]
.Порівняння технологій відстеження рухів кисті
[cols="3,2,2,2",options="header"]
|===
|Критерій |Варіант А |Варіант Б |Варіант В

|Рядок
|значення
|значення
|значення
|===
```

- `cols` задає відносну ширину стовпців. Широкий перший стовпець відводьте під назви критеріїв.
- `options="header"` вмикає рядок заголовка, який повторюється на кожній сторінці.
- Текст у комірках пишеться з малої літери, якщо це не назва, і без крапки в кінці.
- Таблиця має бути повною: порожні комірки не допускаються, замість них ставте «—».

## Формули

```asciidoc
Ступінь розкриття кисті визначається за формулою <<eq-openness>>:

[[eq-openness]]
[stem]
++++
O = \frac{1}{5} \sum_{i=1}^{5} \frac{\lVert p_{tip,i} - p_0 \rVert}{\lVert p_9 - p_0 \rVert},
++++

де stem:[p_0] -- координати зап'ястка;
stem:[p_{tip,i}] -- координати кінчика stem:[i]-го пальця.
```

- Формули записуються в LaTeX, у Word вони стають редагованими формулами.
- Після формули ставиться кома, далі йде пояснення «де …» з переліком **усіх** нових позначень у порядку їх появи.
- Формулу без номера оформлюйте як `[stem,role=nonumber]`.
- Позначення в тексті пишуться так: `stem:[x_i]`.

## Лістинги

```asciidoc
Функцію обчислення кута наведено в лістингу <<lst-angle>>.

[[lst-angle]]
.Обчислення кута згинання суглоба
[source,python]
----
def joint_angle(a, b, c): ...
----
```

В основній частині наводьте короткі фрагменти (до 20–25 рядків), а повний код виносьте в додаток (`chapters/99-appendix-*.adoc`).

## Перевірка

```sh
make check            # кожен fig-/tbl-/eq-/lst- має посилання до свого місця
make && make pdf      # перевірте, що рисунок читається і не виходить за поля
```
