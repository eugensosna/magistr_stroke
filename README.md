# Магістерська робота

Текст пишеться в [AsciiDoc](https://docs.asciidoctor.org/asciidoc/latest/) (`.adoc`),
а зберігається в git. Документ Word (`.docx`) генерується автоматично і оформлюється за:

- **ДСТУ 3008:2015** «Звіти у сфері науки і техніки. Структура та правила оформлювання»;
- **ДСТУ 8302:2015** «Бібліографічне посилання»;
- **Наказом МОН № 40** від 12.01.2017 «Про затвердження Вимог до оформлення дисертації».

## Швидкий старт

```sh
uv run build.py         # -> build/thesis-dev.docx (збірка в контейнері, з примітками рецензента)
uv run build.py pdf     # -> build/thesis-dev.docx і build/thesis-dev.pdf (LibreOffice: оновлює зміст і номери сторінок)
uv run build.py html    # -> build/thesis-preview.html (швидкий перегляд у браузері)
uv run build.py check   # перевірка посилань, джерел, рисунків і таблиць
uv run build.py --release  # -> build/thesis-release.docx: чистова версія без приміток рецензента
uv run build.py review  # перелік зауважень рецензента (відкриті / виправлені)
uv run build.py clean
```

Потрібні лише [uv](https://docs.astral.sh/uv/) і `podman` або `docker`.
Команди однакові для Linux, macOS і Windows (PowerShell або cmd, Docker Desktop з WSL 2).
Перший запуск збере образ `magistr-builder` з asciidoctor, pandoc, python і LibreOffice (кілька хвилин).
Рушій можна вибрати явно: `ENGINE=docker uv run build.py` (у PowerShell: `$env:ENGINE="docker"`).
Без контейнера: `uv run build.py local` (потрібні asciidoctor, pandoc ≥ 3.1, sh).

Під час першого відкриття `thesis-dev.docx` або `thesis-release.docx` Word запропонує **оновити поля**.
Погодьтеся, і зміст заповниться номерами сторінок. Вручну зміст оновлюється так: Ctrl+A, потім F9.
У LibreOffice: «Сервіс → Оновити → Оновити все». Можна також одразу скористатися `uv run build.py pdf`.

## Робота з AI-агентами

`AGENTS.md` (і `CLAUDE.md`, що його імпортує) описує тему, план, глосарій і правила написання.
У `.claude/skills/` лежать skills: `thesis-write` (написання розділів), `thesis-sources`
(пошук і перевірка джерел за ДСТУ 8302:2015), `thesis-figures` (рисунки, таблиці, формули)
і `thesis-review` (нормоконтроль).

## Структура проєкту

```
thesis.adoc               головний файл: порядок структурних елементів
config/attributes.adoc    дані титульного аркуша (ПІБ, тема, кафедра, рік ...)
config/format.toml        параметри оформлення: поля, шрифт, інтервал, відступи
chapters/                 текст роботи, один файл на розділ
images/                   рисунки
build.py                  команди збірки (uv run build.py ...)
Containerfile             образ з asciidoctor, pandoc, python і LibreOffice
tools/                    конвеєр збірки (зазвичай змінювати не потрібно)
  build.sh                AsciiDoc -> HTML -> DOCX
  asciidoctor/dstu_converter.rb
  filters/dstu.lua        нумерація, підписи, формули, джерела за ДСТУ
  make_reference.py       стилі Word з config/format.toml
  postprocess.py          поля, номери сторінок, переліки
  lo_export.py            оновлення змісту і PDF через LibreOffice
```

Новий розділ: створіть `chapters/40-chapter-4.adoc` і додайте `include::` у `thesis.adoc`.

## Як писати

### Поради для git

- **Одне речення — один рядок.** Абзаци розділяються порожнім рядком.
  Тоді `git diff` показує зміни по реченнях, а конфлікти злиття трапляються рідко.
- Комітьте лише джерела. Каталог `build/` ігнорується.
- Рисунки зберігайте у `images/`. Діаграми краще тримати у вихідному форматі
  (наприклад `.drawio`, `.puml`) поруч із PNG.

### Розділи

```asciidoc
[[ch-analysis]]
== Аналіз предметної області          -> РОЗДІЛ 1 / АНАЛІЗ ПРЕДМЕТНОЇ ОБЛАСТІ (з нової сторінки)

=== Огляд рішень                      -> 1.1 Огляд рішень
==== Пункт                            -> 1.1.1 Пункт
```

Вступ, висновки, список джерел та інші структурні елементи розпізнаються за назвою
і не нумеруються. Довільний розділ без номера позначається `[.unnumbered]`, а розділ,
якого не має бути в змісті, позначається `[.notoc]`. Додатки позначаються `[appendix]` і отримують
літери А, Б, В … (без Ґ, Є, З, І, Ї, Й, О, Ч, Ь), їхні підрозділи нумеруються А.1, А.2.

### Рисунки, таблиці, формули, лістинги

Номери ставляться автоматично в межах розділу (1.1, 1.2, …, у додатках А.1).
Посилання `<<id>>` без тексту перетворюється на номер.

````asciidoc
Структуру наведено на рис. <<fig-arch>>.

[[fig-arch]]
.Архітектура системи                 -> «Рисунок 1.1 – Архітектура системи» під рисунком
image::arch.png[Архітектура,width=80%]

[[tbl-cmp]]
.Порівняння рішень                   -> «Таблиця 1.1 – Порівняння рішень» над таблицею
[cols="2,1,1",options="header"]
|===
|Критерій |А |Б
|Ціна |висока |низька
|===

[[eq-time]]
[stem]
++++
T = \sum_{i=1}^{n} t_i               -> формула по центру, (1.1) біля правого поля
++++
Згідно з формулою <<eq-time>> ...     -> «формулою (1.1)»

[stem,role=nonumber]                  -> формула без номера

[[lst-main]]
.Головний модуль                      -> «Лістинг 1.1 – Головний модуль»
[source,python]
----
print("hello")
----
````

Формули записуються в LaTeX. У рядку тексту: `stem:[x^2]`. У Word вони стають
звичайними редагованими формулами.

### Список використаних джерел (ДСТУ 8302:2015)

Файл `chapters/95-references.adoc`. Кожне джерело записується одним рядком у вигляді
бібліографічного опису за ДСТУ 8302:2015:

```asciidoc
* [[[petrenko2024]]] Петренко О. І. Назва книги. Київ : Наук. думка, 2024. 250 с.
```

Посилання в тексті: `<<petrenko2024>>` дає `[1]`, а `<<petrenko2024,с. 15>>` дає `[1, с. 15]`.
Номери присвоюються в порядку елементів списку. Розташуйте джерела в порядку першої
згадки в тексті або за абеткою, як вимагає кафедра.

### Інше

| Що                         | Як написати                         | Результат                        |
|----------------------------|-------------------------------------|----------------------------------|
| маркований перелік         | `* пункт`                           | «– пункт»                        |
| нумерований перелік        | `. пункт`                           | «1) пункт»                       |
| перелік з літерами         | `[loweralpha]` + `. пункт`          | «а) пункт»                       |
| виноска                    | `текст.footnote:[Пояснення.]`       | виноска внизу сторінки           |
| примітка                   | `NOTE: текст`                       | «Примітка. текст»                |
| скорочення                 | `ДСТУ:: державний стандарт України` | «ДСТУ – державний стандарт України» |
| розрив сторінки            | `<<<`                               |                                  |
| абзац по центру/без відступу | `[.center]` / `[.noindent]`       |                                  |

## Налаштування під вимоги кафедри

- Поля, шрифт, кегль, інтервал, абзацний відступ і розташування номера сторінки
  змінюються в `config/format.toml`.
- Титульний аркуш зібрано в `chapters/00-titlepage.adoc`, дані для нього беруться з
  `config/attributes.adoc`. Вертикальні відступи регулюються кількістю рядків `{nbsp}`.
- Підписи («Рисунок», «Таблиця», «РОЗДІЛ», «ДОДАТОК») задано в таблиці `LABEL`
  на початку `tools/filters/dstu.lua`.

Значення за замовчуванням: А4, поля ліве 30 мм, праве 15 мм, верхнє та нижнє 20 мм,
Times New Roman 14 пт, інтервал 1,5, абзацний відступ 1,25 см, вирівнювання за шириною.
Номер сторінки стоїть у правому верхньому куті, на титульному аркуші його не видно,
але він враховується.
