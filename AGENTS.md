# AGENTS.md — інструкції для AI-агентів

Репозиторій містить магістерську роботу (кваліфікаційну роботу магістра), написану в AsciiDoc.
З неї автоматично генерується DOCX, оформлений за ДСТУ 3008:2015, ДСТУ 8302:2015 і Наказом МОН № 40.

**Тема:** «Ігровий застосунок для дистанційної реабілітації пацієнтів з порушенням дрібної
моторики на основі технологій комп'ютерного зору».

**Мова роботи:** українська (академічний стиль). Анотація також англійською.

## Команди

```sh
make                       # build/thesis.docx (у контейнері podman/docker)
make pdf                   # build/thesis.pdf через LibreOffice (з оновленим змістом)
make check                 # перевірка посилань, джерел, рисунків, таблиць
python3 tools/check.py --sort-bib   # впорядкувати джерела за першим посиланням
```

Після будь-якої зміни тексту запускайте `make check`, а після суттєвих змін — `make && make pdf`.
Перегляньте сторінки PDF (`pdftoppm -r 60 -png build/thesis.pdf /tmp/p`) і переконайтеся, що верстка не зламалася.

## Структура

| Шлях | Зміст |
|---|---|
| `thesis.adoc` | головний файл, порядок структурних елементів (include) |
| `config/attributes.adoc` | дані титульного аркуша, тема, ПІБ, рік |
| `config/format.toml` | поля, шрифт, інтервали (вимоги кафедри) |
| `chapters/NN-*.adoc` | текст, один файл на структурний елемент або розділ |
| `chapters/95-references.adoc` | список використаних джерел |
| `images/*.png` | рисунки, що вставляються в роботу |
| `images/src/*.svg` | вихідні файли схем (редагуються вони, PNG генерується) |
| `tools/` | конвеєр збірки. Не змінюйте його без потреби |
| `build/` | результати збірки. Не редагуйте вручну, не комітьте |

Що вже зафіксовано в розділі 1 і має узгоджуватися з подальшими розділами:

- **Відстеження кисті.** Застосовується MediaPipe Hands: 21 ключова точка у форматі 2,5D, звичайна вебкамера, обробка на пристрої пацієнта.
- **Показники.** Застосунок обчислює кути згинання суглобів пальців, відстань між кінчиками пальців, ступінь розкриття кисті, частоту і ритм рухів. Показники нормуються на розмір кисті, перед вправами проводиться калібрування.
- **Вправи.** Щипковий захват, протиставлення великого пальця, розкриття і стискання кисті, ізольовані рухи пальців. Складність адаптується до можливостей пацієнта.
- **Архітектура.** Клієнтський застосунок, сервер з журналом сеансів, кабінет фахівця. На сервер передаються лише числові показники, відео з пристрою не передається.
- **Завдання дослідження.** П'ять завдань, перелічених у підрозділі 1.5. Їх треба повторити у вступі й закрити у висновках.

## Правила написання (обов'язкові)

1. **Одне речення — один рядок.** Абзаци розділяються порожнім рядком. Так diff у git лишається читабельним.
2. **Нумерація автоматична.** Не пишіть номери розділів, рисунків, таблиць і формул вручну.
   Посилання оформлюються так: `рис. <<fig-id>>`, `табл. <<tbl-id>>`, `формулою <<eq-id>>`, `підрозділі <<sec-id>>`.
3. **Ідентифікатори** пишуться латиницею з префіксами: `ch-`, `sec-`, `fig-`, `tbl-`, `eq-`, `lst-`, `app-`.
   Кожен рисунок, таблиця, формула з номером і лістинг повинні мати посилання в тексті, причому посилання має стояти **до** самого об'єкта.
4. **Джерела.** Посилання пишеться як `<<id>>` (дає [n]) або `<<id,с. 15>>` (дає [n, с. 15]).
   **Ніколи не вигадуйте джерела, авторів, DOI, сторінки чи числові результати.**
   Кожне нове джерело перевіряйте через Crossref або офіційний сайт (див. skill `thesis-sources`).
   Факти з джерела переказуйте лише так, як вони сформульовані в його анотації або тексті.
5. **Стиль.** Академічний, безособовий («розглянуто», «запропоновано», «у роботі показано»), без «я» і «ми».
   Не використовуйте розмовних слів і калік з російської та англійської. Терміни мають бути сталими (див. глосарій нижче).
6. **Структура розділу.** Розділ починається вступним абзацом і завершується підрозділом «Висновки до розділу N» з нумерованими висновками.
7. Не змінюйте `tools/`, `config/format.toml`, `Makefile` у межах завдання з написання тексту, якщо про це не просили.
8. Не комітьте без прохання користувача.

## Skills

У `.claude/skills/` є такі skills:

- `thesis-write` — написання або редагування розділу чи підрозділу;
- `thesis-sources` — пошук, перевірка й оформлення джерел за ДСТУ 8302:2015;
- `thesis-figures` — рисунки (SVG → PNG), таблиці, формули;
- `thesis-review` — нормоконтроль: збірка, перевірки, огляд верстки і тексту.
